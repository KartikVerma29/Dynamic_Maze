================================================================================
  DYNAMIC MAZE — COMPLETE SYSTEM DESIGN REFERENCE
  All Levels (L1 → L4) · C++ · Raylib · WebAssembly
================================================================================

────────────────────────────────────────────────────────────────────────────────
DESIGN PATTERNS USED
────────────────────────────────────────────────────────────────────────────────
  Observer       → EventManager, IEventListener<T>, IEventPublisher<T>
  Strategy       → IMazeGenerator, ISolvabilityChecker, IPathfinder, IScoreCalculator
  State          → IAppState, ModeManager
  Adapter+Facade → RaylibRenderer
  Factory        → (deferred to implementation)
  Dependency Injection → all interfaces injected via constructor

────────────────────────────────────────────────────────────────────────────────
UML RELATIONSHIP NOTATION
────────────────────────────────────────────────────────────────────────────────
  ◆  Composition  — strong ownership, child dies with parent
  ◇  Aggregation  — weak ownership, DI injected, child can exist alone
  →  Inheritance  — solid line + hollow triangle (is-a, extends)
  ⇢  Realization  — dashed line + hollow triangle (implements interface)
  --► Dependency  — dashed + open arrow (uses, publishes)
