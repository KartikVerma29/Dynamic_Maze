Dynamic Maze — Game Design Requirements
Full specification · v0.1 · C/C++ + Raylib + WebAssembly
Core Concept
A maze game where the layout is never fixed. Walls shift based on rules, multiple solutions exist at any time but keep changing — unlike classical static mazes. Always solvable, never cage the player.

Core Rules (all modes)
Maze changes after X steps (primary trigger) + small random variance ±10–20 steps so it's not predictable
Maze changes target the path player is currently following — partial wall shifts, not full resets
Solvability always maintained — at least one valid path exists at every state
Player is never caged during a layout change
3 lives → game over (classical system)
Player movement: free/smooth (not grid-snapped)
View: top-down 2D, simple graphics for now
Game Modes
Mode 1
Dynamic Maze
Shifting maze, find the exit. Multiple levels (4–5). Maze size grows per level. Enemies optional (zero by default). Speed fixed.
Mode 2
Dark Maze
Limited light radius, no map. Player chooses dynamic or static maze. 4–5 levels. No enemies. Speed fixed. Explores memory + navigation.
Mode 3
Gauntlet
Pac-Man + dynamic maze twist. Endless run. Enemies scale with difficulty. Speed increases over time. Idle punished by wall opening or enemy spawn.
Maze Structure (Phase 1)
Grid Maze
Standard cell-based grid. Walls shift between cells. Classic maze feel. Easier to implement solvability checks.
Concentric Ring Maze
Rings rotate independently AND walls shift. Maze Runner feel. More mechanical and chaotic.
Phase 2 (later): mixed grid+ring, asymmetric layouts

Enemies (Gauntlet Mode Only)
Chaser
Cannot be defeated. Follows player (BFS pathfinding). Avoid only.
Patrol
Defeatable by collision from behind (opposite to movement direction).
Blocker
Immortal when stationary. Defeatable from either side when moving.
Attack mechanic: simple collision (no button press). Enemy count scales with difficulty.
